# USB

* Universal Serial Bus (он же USB) - универсальная последовательная шина
	* Она двунаправленная
	* Передает данные старшими разрядами вперед
	* Физически представляет собой витую пару с двумя сигнальными линиями
* Разработка стандарта инициирована авторитетными компаниями (Intel, IBM, DEC, NEC)
* Первая версия - 15 января 1996 года

#### А нахуя его создавали

* Нужен он, чтобы через него подключать на горячую. А для этого нужны следующие моменты:
	* Подключение/отключение к работающему ПК, само подключение прозрачно для пользователя
	* Должно обеспечиваться питание для маломощных устройств
	* Устройство должно распознаваться сразу при факте подключения (а для этого были диски с драйверами)
	* Скорость передачи данных по шине должна быть достаточной для большинства периферийных устройств, в т.ч. и для видеокамер (тут это было впервые)

* Еще можно отметить, что было важным, чтоб было только одно прерывание для USB-контроллера вне зависимости от количества подключенных устройств.

### Технические характеристики (для первой версии)

* Низкая скорость (low-speed) - 1,5 Мбит/с
* Высокая скорость (fuk-speed) - 12 Мбит/с
* Макс. длина кабеля для low-speed - 3 м
	* Тут это обосновывается низким качеством кабеля, он был без экранирования
* Макс. длина кабеля для full-speed - 5 м
	* А для такой скорости уже нужен хороший экранированный кабель (раньше он был в 2-2,5 раза)
* Макс. количество устройств - 127
* Напряжение питания для периферийных устройств (и самого интерфейса) - 5 В
* Максимальный ток на одно устройство - 500 мА
* Отсутствие необходимости подключать дополнительные элементы - интерфейс сам по себе полноценный

### Эволюция интерфейса

* Поначалу он никому не усрался, так как разработка стандарта немного так опередила разработчиков чипов
* Потом некоторые крупные игроки поняли, что он хорош

* А как он развивался
	* В 1.1 как раз появился full-speed
	* В 2.0 появился high-speed - 480 Мбит/с
	* В 3.0 и 3.1 gen 1 появился superspeed - до 5 Гбит/с
	* В 3.1 gen 2 superspeed+10Gbit стал до 10 Гбит/с
	* В 3.2 gen 2 superspeed стал до 20 Гбит/с
### Физическая реализация интерфейса

* Там 4 контакта:
	* Выступающие - питание и земля. Тогда устройство запитывается еще до передачи, а выключается после прерывания передачи
	* Не выступающие - каналы передачи

* Вариации
	* Type A - стандартная, всем привычная прямоугольная версия
	* Type B - по форме как домик. Используется в принтерах, некоторых аудиоустройствах
	* Mini - маленький USB

* Откуда те ебнутые скорости - USB работает по принципу No Return To Zero (кодом NRZI, привет моделированию).
* Тогда банально переключений меньше, так что он на них времени меньше тратит
	* Кстати, тут NRZI немного особенное - если подряд идет более 6 единиц, то после шестой вставится ноль
	* Напомню, что там кодируется количеством переключений: 0 - нет переключений; 1 - есть переключение

* Кстати, переключается он перекрестно - D+ источника к D- приемника, а D+ приемника - к D- источника
* Если на D+ подключенного повесить резистор, то тогда оно будет считаться по low-speed
* Если на сам девайс (ПК) повесить резитор на D-, то тогда подключаемое будет считаться full-speed

* Node - устройство-функция
* Hub - буквально разветвитель/хаб

* Хаб занимается электрическим согласованием кабеля. У него может быть свое питание, но управлять ими он никогда не сможет. Но может еще управлять пакетами или подключать/отключать устройства-функции
* Устройство-функция - конечный девайс. Он может быть оснащен портом USB (т.е. быть и хабом одновременно)
* Тут невозможно получить замкнутую цепь

#### Электропитание
* На USB 2.0 уже было питание с током до 0,5 А и 5 В
* USB 3.0 - ток 0,9 А при тех же 5 В
* Дальше уже из-за питания телефонов от банок появилась спецификация USB Battery Charging, поднимающая ток до 5 А

### А помните про адресацию?

* В процессе подключения происходит согласование устройств, конфигурирование итд
* Адресов до 127.
	* 0 зарезервирован для подключения устройства. После конфигурирования он получает уже конкретный адрес, 0 освобождается для той же задачи, но с другими устройствами

### Методы обмена данными

* Control, Bulk, Interrupt и Isochronous
* Первые три используют протокол обмена с подтверждением (что-то типа TCP)
* Bulk позволяет хост-контроллеру обмениваться данными с подключенными по своему усмотрению. Но он с самым низким приоритетом
* Control - как Bulk, только для специальных данных, управляющих устройствами
* Передачу инициализирует только Host. Так что подключенные устройства инициализируют метод Interrupt (прерывание). Он позволяет считывать данные с клавиатуры/мыши
	* Сам host уже потом раз в определенный период опращивает на 
* Метод Isochronous используется для обмена сжатыми видеоданными. Он требует резервирование полосы канала, так что много камер вы не подключите
	* Он не поддерживает контроля целостности, так что если данные нормально не дошли (дошли поврежденными или не смогли обработать), то они потеряются.
	* В данном случае это хорошее решение. Как ты планируешь вставлять дополученный кадр? Да и процедуры согласования получения пакетов - довольно-таки длительные процессы, что пиздец как палятся на видео/аудио

### Пакетная передача

* Обмен идет короткими пакетами 
* Каждый пакет начинается с последовательности Start of Packet (спец. последовательность сигналов на шине). Потом идет PID (Packet Identificator)
	* Всего в USB 16 видов пакетов, так что для их определения используется 4 бита. Для достоверности его дублируют, но в инверсном виде.
* Пакет заканчивается последовательностью End of Packet

* Последовательность пакетов - Token-> Data -> Handshale
	* Token - тип пакета, источник, приемник
	* Data - сами данные
	* Handshake - подтверждение получения/неполучения пакета
