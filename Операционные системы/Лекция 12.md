# Обработка прерываний
* Процессор 86 обеспечивает создание таблицы IDT (таблицы прерываний). 
* Она содержится в единственном количестве
* Также есть регистр IDTR - указывает на первый элемент таблицы
* В таблице хранятся дескрипторы-шлюзы - коммутаторы

* Прерывания делятся на 3 группы:
	1. INT_gate - коммутатор прерывания
	2. Коммутатор ловушки
	3. task_gate

* К таблице обращаются при помощи суммирования IDTR и номера прерывания.
* Из нужного сегмента берется поле селектора, по которому обращаются к ячейке LDT/GDT, откуда извлекается адрес сегмента.
	* Такое обращение применимо к первым двум типам прерывания
	* Третий тип - это переключение задач

* Прерывания INT_gate (Interruption gate) - это форс-мажорные прерывания. При них система прерывания отключается
* При втором типе она не отключается, т.к. эти прерывания являются программными (с не высоким рейтингом). Это открытые прерывания
* Третий тип - а он не используется %%СОСАААААААТЬ%%. Переключение задач - процесс затратный.

# Итоги по процессору x86
* Процессор может работать в двух режимах:
	1. Реальный (однозадачный)
	2. Многозадачный (обеспечивает 32-бит разрядную шину)

* Основной способ организации памяти - сегмент.
* Каждому сегменту соответствует дескриптор - 8-байтовая структура.
* Дескрипторы объединяются в LDT. Сколько задач, столько LDT.
* Есть одна общая GDT. Там хранятся дескрипторы ядра, дескрипторы шлюзов и дескрипторы для первых сегментов КАЖДОЙ LDT. Максимальный размер таблицы - 64КБ
* При сегментной организации памяти линейный адрес определяется при обращении к GDT/LDT (за это отвечает бит TI)
* При сегментной организации памяти есть скрытый сегмент - хранит дескриптор текущего сегмента.

* Процессор обеспечивает 4 уровня приведений
	1. Для ядра
	2. Для утилит
	3. Не используется
	4. Для прикладных программ

* Права доступа к разным типам сегментов отличаются. Основа у них - сравнение DPL и RPL
  
* Есть такая штука, как подчиненный сегмент.
* Для обращения к неподчиненному сегменту используется шлюз
  
  * Еще один вариант организации памяти - сегментно-страничный
	  * Об этом говорит бит CR0 (она равна 1 при сегментно-страничной организации)
	  * Тогда полученный сегментный адрес рассматривается как виртуальный
	  * Вводятся понятия как каталог разделов и таблица страниц
	  * Каждой странице соответствует дескриптор
	  * Такой дескриптор 4 байта
	  * Такая организация медленная
  * Для ускорения используется спец. устройство - TLB - буфер ассоциативной трансляции, кеш-память для дескрипторов страниц. Состоит из 8 блоков по 4 дескриптора.
	  * Такая память небольшая
	  * Если все слоты заполнены, то решается задача замещения при помощи упрощенной процедуры LRU (Least Recently Used)

* Переключение задач.
	* Контекст задачи надо поменять для переключения на новую задачу
		* Для этого используется сегмент TSS, в котором указывается TR.
		* Там хранится контекст
			* Лежат устройства ввода-вывода
			* Значения регистров, что должны загрузиться в памяти
		* TSS текущей выгружается
		* Ищется TSS новой задачи
		* Этот TSS загружается
		* Все, теперь выполняется новая задача
