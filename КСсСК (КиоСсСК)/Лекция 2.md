# Нелегальные IP-адреса
* Таких адресов быть не должно. Они допустимы только в Intranet - внутренняя сеть. В такие сети извне не попасть, так как при его указании тебя просто не пустят
* Они лежат в определенных диапазонах
	* 10.X.X.X - у нее самое большое адресное пространство (класс А)
		* Например, в обычном классе адреса имели бы вид: 10.32.4.X
		* В ГУАП принято, что второй октет - "номер_корпуса_номер_этажа"
	* 172.16.X.X-172.31.X.X - сети класса B
	* 192.168.X.X - сети класса C
* Для связи между Intranet и Internet должно быть устройство (ПК) с двумя сетевыми интерфейсами (по одному на Intra и Inter).
* Этот ПК будет выступать как прокси-сервер.
	* Он меняет адреса отправителя и получателя на свой и легальный, причем он делает пометку, кто и какой запрос фактически делал. За это отвечает NAT
	* Ответ он запишет в виде кеш-файла.

* А вот взаимодействие между двумя Intranet отвечает VPN) На обоих сторонах стоят сервера, которые и передают запросы через Internet.

* За распределение и выдачу ip-адрессов и имен к ним отвечает компания ICANN

* Есть два вида назначения IP-адресов:
	* Статический (вручную). Такой способ был основным, до 1992 года. Тогда появился DHCP - Dynamic Host Connection Protocol (от Microsoft)
		* Он создан на основе BOOTP (Boot Protocol - протокол загрузки)
		* PXE - протокол, который вынуждает сетевой адаптер при включении ПК отправлять широковещательные запросы на предмет получения кода ОС Unix
			* Благодаря PXE отправлялся код ядра, которое сохранялось при помощи BOOTP на ПК. Он там кмопилировался, этому устройству выдавался IP - и теперь он работает как терминал для сервера.
			* Этим занималась компания SUN (Java, )
		* DHCP работает по принципу DORA
			* Discovery - обнаружение. Отправлялся широковещательный запрос, для присвоения себе адреса. Если адрес получен, то проверяется его конфликтность. Нет конфликтов - адрес твой.
				* Сейчас за это отвечает протокол APIPA (Automatic Privae IP Addressing). 
				* За выдачу отвечает DHCP-сервер со своими областями адресов. Такие области называется Scope
			* Offer - ответ от DCHP-сервера, что есть доступный (доступные) адреса. И ПК с таймаутами выбирает себе адрес. Таймауты и выбор использовались, чтобы избежать захвата ПК по сети.
			* Request - ответ конкретному серверу, от которого клиент решил взять IP.
				* Если сервер назад не получает Request, то он считает, что этот адрес все еще можно предлагать другим клиентам.
				* Порты 67 и 68 используются для ответов от клиентов
			* (not)Acknowledge - ответ от сервера на Request, в котором передаются вспомогательные данные (более 100 параметров, хотя пересылаются не все).
				* Один из таких параметров -Leasing time - время аренды (оно назначается администратором сервера).
				* По истечении ПОЛОВИНЫ времени аренды клиент пытается продлить аренду. Если он не смог продлить аренду, то по ее истечению он присвоит себе адрес 0.0.0.0
		* Адреса через DHCP НЕЛЬЗЯ задавать IP на некоторые устройства:
			* Маршрутизаторы должны иметь только статические IP-адреса
			* DHCP-сервера должны иметь только статические IP
			* Сервера имен также должны иметь только статические IP
			* Сервера времени - только со статическими IP
			* Контроллер домена должен иметь только статический IP
				* И ЕЩЕ У НЕГО ТОЛЬКО ОДИН СЕТЕВОЙ АДАПТЕР
		* Когда мы создаем области, мы должны указывать их диапазон. Проблема - в таких диапазонах могут быть устройства со статическими IP.
			* В винде есть для этого инструменты по созданию исключений, их мы обязаны указывать. Ну и еще надо указывать IP сервера, на котором область и формируется.
			* IP-адреса еще модно резервировать, связывая MAC и IP.
				* Для Astra Linux используется протокол isc-dhcp-server (но там нет исключений)
				* Поэтому там они делаются через резервирования, которое делается через ARP-протокол. IP можно узнать через ip a или ipconfig (последний делается через sudo)
				* на винде для этого есть ipconfig
