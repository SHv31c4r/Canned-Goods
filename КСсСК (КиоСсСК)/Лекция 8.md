### SACL

* При редактировании SACL/DACL эти разрешения могут унаследоваться на файлы с самыми разными результатами
* Находится SACL во вкладке "Аудит" в поле "Безопасность" в свойствах
* Там можно указать пользователя. А так как их может быть много, то при заполнении можно проверить, правильно ли записан его логин:
	* Этот логин имеет вид `Имя (домен)`
	* Хотя есть еще вид `\\domain \login`
* Следует помнить, что эти все штуки следует делать не на пользователя, а на группу

* В самом SACL у каждого правила есть два поля:
	* Успех - это действие разрешено, но оно будет зафиксировано в журнале аудита
	* Отказ - действие запрещено, запись о попытке данного действия появится в журнале аудита

* После настройки аудит вестись не будет. Потому что эта штука завязана на прерываниях, а они тратят время и ресурсы. Поэтому эта штука хоть как-то работает на серверах
* Политика - механизм изменений параметров, не залезая в файл политики (какие-то конфиги для системного ПО, по сути). Например, правка параметров реестра, когда пользователь садится за пк, за которым он не работал: сразу какие-то правила подтянутся, но пользователь не сможет их править (если такая политика выставлена)
	* В современных Windows этих правил порядка 8к

* Политика безопасности контроллера домена - правила, которые применяются на все устройства, которые являются контроллерами домена. Они все лежат в отдельном контейнере для контроллеров домене.
* Политики применяются сразу же после их изменения

### Базовые понятия, связанные с доменом

* Домены обозначаются треугольником.
* Сервер, где лежат все учетки - это контроллер домена (DC - Domain Contorller)
	* Если домен небольшой, то достаточно и одного домена. Но если он ляжет - то ничего сделать не получится
	* Так что на системах на 50 компов лучше ставить еще и резервный
	* Есть Primary DC (PDC) - на нем лежала главная запись каталога, данные по учеткам, служба каталога и ее файлы итд
	* Есть еще Backup DC (BDC). На него реплицировалась служба каталога с основного контроллера домена
	* Еще есть прикол с локальной и глобальной учеткой, когда  ПК есть в доменной сети
		* Если пользователь зашел с локальной учеткой, то он не может работать с доменом. Хотя домен этот пк видит
		* Если же это действие сделать с ПК, которого нет в домене, то этот ПК бдует послан нахуй контроллером

* Хозяин домена - тот контроллер домена, который был первым при создании домена.
	* Хозяина можно поменять

* В DNS в интернете домен может иметь поддомены. Такая же штука есть и в службе каталога.
	* У домена firma.local вполне спокойно может быть поддомен fil1.firma.local
	* У такого поддомена должен быть свой контроллер со своими ПК, админами.
	* И им можно предоставлять ресурсы
		* Администраторы поддомены могут получать ресурсы из домена выше на правах пользователей на доверительных отношениях
	* Администраторы в основном домене ВСЕГДА являются администраторами поддомена
	* Но админы поддомена только у себя админы. В другие домены они могут соваться только если есть отношения доверия между доменами
	* В рамках одного домена все друг другу делать. Но это применимо только к Active Directory. Эти отношения были двусторонними, хотя в остальных случаях доверие было односторонним (односторонняя так же является более старой)

* К домену local нельзя подключиться извне через интернет
* Для этого используют специальные легальные доменные имена
* И создавался такой специальный домен с тем же именем, только старшая часть менялась с local на com, например
* Чтобы это работало, придумали лес доменов
* Лес может состоять минимум из одного дерева с одним корнем. Так делают мелкие предприятия
* У крупных компаний в лесу несколько деревьев с очень глубокой структурой

* Даже если у нас есть один домен, не факт, что он рАвно быстродействующий ко всем своим устройствам
* Сайт по умолчанию (Defaullt FIrst Site).
* Сайт - такое подмножество контроллеров домена, между которыми есть высокоскоротсное соединение.
	* Внутри сайта репликации проводятся так же, как описано выше.
	* Но между сайтами репликация проводится по расписанию, установленному администраторами.

* Подразделение (Organizational Unit - OU) - контейнер, в котором могут быть другие подразделения.
* Их можно структурировать до 7 подразделений вниз
* Такой метод считается основным
