# NTFS

* NTFS должна была обладать некоторыми свойствами, которых в FAT (File Allocation Table) не было
	* Например, при потере питания во время записи изменений основная таблица FAT могла сломаться
	* Для починки просто на место основной таблицы записывалась резервная

* Сам же NTFS основан на логгировании действий над файлами
	* Когда открывается файл, в файле журнала тома (специальный внутрисистемный файл) делается запись, что такой-то файл был открыт
	* И в процессе изменения в этот файлик пишутся изменения.
	* Файл был закрыт с сохранением (операция завершилась) -> в описателе файла обновляются списки кластеров, на которых размещен файл.
		* По сути, тут та же механика, что и с транзакциями в БД
	* Иначе - специальная прога устанавливает, что старый описатель - самый новый по версии. А фактически более новые описатели отлетают в небытие нахуй

* На низкоуровневом форматировании проверяются кластеры на их способность записывать и быть считанными.
* В NTFS при высокоуровневом форматировании резервируют несколько тысяч блоков. И если там возникают ошибки, то каждый блок читается по 100 раз, то блоки помечаются как резервные, а плохой блок так и помечается, чтоб его не использовать.

* Дискреционный метод изначально применялся для доступа к сетевым ресурсам, а не к файловой системе
* **и тут мы смотрели на WinNT то, что разбирали на прошлой лекции; как оно там выглядит**

* Админы в такой системе как в колхозе: у них все общее
* У micropenis есть следующие разрешение
	* Атомарный - самый базовый набор разрешений (одна колонка в таблице, фактически)
	* Стандартные - Наборы разрешений для повседневного использования (в NT там их 7)
		* No Access - нет никакого доступа. Вообще
		* List - просмотр. Разрешается просматривать только каталоги (на них висят атомарные права RX). Файлы так же под запертом
		* Read - чтение. На каталоги и файлы одни и те же атомарные права - RX
		* Add - добавление. Можно просматривать каталоги и создавать в них файлы. Сами же файлы никак трогать нельзя.
		* Add & Read - суммирование прав с предыдущих двух наборов
		* Modify
		* Full Control
	* Специальные - наборы разрешений, которые мы сами делаем из имеющихся для конкретных целей

* А какие группы у нас есть локальные?
	* Administrators - админы
	* Backup Operators - специальная группа для челов, которые делают бекапы. Могут их делать, могут с них восстанавливаться. Но все то, что они бекапят, они прочитать не могут.
	* Guests - гости. У них нет своего рабочего стола и личной папки. При выходе их изменения теряются, но они могут сохранять в выделенные для этого папки.
	* Power Users - сильные пользователи
	* Replicators - пользователь для обеспечения репликации данных между основным и резервным серверами, например. В основном это боты

* ПРАВА ДАЮТСЯ НА КЛАССЫ ОБЪЕКТОВ (нет возможности работать с конкретными файлами), РАЗРЕШЕНИЯ (пермиссии/Permissions) ДАЮТСЯ НА МНОЖЕСТВА ФАЙЛОВ
	* В этом разница между правами и разрешениями

* В NTFS есть два списка для управления доступом
	* DACL - Discretionary Access Conttol List
	* SACL - System Access Control LIst - по умолчанию пустой, его могут делать только админы. С ним можно делать аудит для доступа к файлам (можно даже на определенные изменения в папке делать)
		* Проблема аудита - его нужно читать, а это нихуя себе какой файлик.

* Какие там есть стандартные разрешения:
	* Полный доступ - в представлении не нуждается
	* Изменить (Modify)
	* Чтение и выполнение (Read & Execute) - идут вместе, но можно их по отдельности задавать
	* Список содержимого папки - специальное разрешение чисто для каталога
	* Чтение 
	* Запись
	* Особые разрешения (Specific Permissions) - они написаны в разделе дополнительно. Например, можно давать специальные разрешения
