# Маршрутизация

* Вводная инфа: по OSI данные делятся на пакеты. Их надо передавать. Но передать данные между двумя разными сетями просто так нельзя. Нужно составить **маршрут**, который может проходить через одну или несколько других сетей.
  
Пусть будет сеть 10.22.7.0/24
В этой сети есть узлы
Сам сервер имеет адрес 10.22.7.254/24
* Примечание
	* Маршрутизатор и  шлюз - это разные вещи
	* Шлюз - устройство для перехода в другое пространство
И сервер подключается в еще одну сеть - 172.20.7.0/24
И там его ip 172.20.7.0/24
Тогда он уже становится шлюзом между двумя сетями
* Таблица маршрутизации - набор правил в виде таблицы, там описано, через который из шлюзов ты можешь пройти
	* Вот например, есть третья сеть - 172.168.7.0/24
	* В нее можно попасть из второй сети по устройству с ip 127.20.7.1
	* И тогда вот это вот второе устройство будет МАРШРУТИЗАТОРОМ для первой сети

* Сам интернет очень большой (миллионы сетей). И это может быть максимально нестабильно: кто-то перегрыз кабель/ перезагружал сервер
* Поэтому используется динамическая маршрутизация
	* Она, как правило, реализуется в дорогих маршрутизаторах
	* Но ее можно сделать и на сервере, в котором просто много портов
	  
	* Есть протокол RIP - протокол сбора информации.
		* Роутер с этим протоколом опросит своих ближайших соседей, которые уже опросят своих соседей.
		* Это называется хопами. Хопов может быть до 16
		* ВАЖНО!!! Этот RIP должен еще быть и на тех роутерах, к которым обращаются, иначе он захлебывается/не понимает
		* Проблема - RIP может порождать далеко не оптимальные маршруты
	
	* OSPF - Open Shortest Path First
		*  Это уже протокол, который оптимизирует таблицу, полученную через RIP
		* Он считает не только количество роутеров на пути, но еще и вес (он записывается в метрику)
* Есть еще и статическая маршрутизация
	* Она уже имеет смысл только когда человек сам грамотно эти таблицы маршрутизаций пишет
	* Такое применяется в рамках сети условной организации.

* Про четвертую лр:
	* Она из трех частей
	* Надо взять две виртуальные сети и написать таблицу маршрутизации
	* Во второй части надо соединить 

* Есть разные маршрутизаторы, под разные цены. Самые известные - от Cisco

# TCP/IP 6

* Он автоконфигурируем (ему не нужны ни DHCP, ни маршрутизаторы)

* Адрес по нему из 128 бит
	* Для удобства его делят на 16-битные 16-ричные числа, разделённые двоеточиями (по итогу в одной такой части 4 шестнадцатеричных числа)
	* Его можно сократить, если в этой четверке все нули, но такое сокращение должно быть только ОДНО
	* Таких четверок должно быть 8
	* В рамках одной секции можно опустить все старшие нули, НО ТОЛЬКО В РАМКАХ СЕКЦИИ
		* Но не забывайте, что сокращение нулевых четверок можно использовать только один раз

* Этот адрес разбивается на группы:
	* первые 3 четверки - префикс глобальной маршрутизации
		* Назначается провайдером, мы его не трогаем
	* 4-я четверка - номер подсети
	* Остальное - идентификатор интерфейса
	* ну и так же указываются через / количество битов на идентификацию сети

* Нюансы
	* Нет широковещательных адресов. Вместо него - multicasting.
	* Использует MAC адреса, только конвертит идентификатор путем дописывания в середину FF:FE (?)
	* Маски для подсетей работают так же
	* Минимальная оптимальная маска - 64
	* unicast - одноадресные адреса для однозначной идентификации устройства. крч, классический ip-адрес.
	* Интерфейс может иметь более одного адреса (можно на один интерфейс сразу и адрес ipv4, и адрес ipv6)
		* Если вдруг вы написали некорректный ipv6, то надо его отменить, иначе правильный адрес запишется как второй
