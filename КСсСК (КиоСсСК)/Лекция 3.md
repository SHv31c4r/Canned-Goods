# DNS

### Domain Name System - система доменных имен
* Она позволяет использовать символьные имена узлов в IP-сетях, что делает их более информативными
* Появился он в 1984 году
	* Это на два года позже, чем сам интернет
	* Вместо него использовали специальные текстовые файлы hosts
		* Их заполняли вручную
		* И они должны быть одинаковыми по стилю
		* Поэтому был один челик, который этот файл составлял (ему можно было отправить свои пожеланий). И в 00:00 понедельника этот обновленный файл hosts отправлялся всем участникам сети. Короче, геморрой редкостный
* Сама она организован как распределенная БД и обеспечивает:
	* обновление БД;
	* распространение информации между DNS-серверами (сервер с этой БД)
	* обслуживание запросов на разрешение имени
* В каждом домене такая БД своя. Иногда она может хранить и поддомены
	* И такая БД называется зоной
* Доменное имя может быть максимум 256 символов

* **Тут домен - это множество объектов, объединенных под одним именем. А не множество компьютеров, где есть сервер с логинами и паролями для всех аккаунтов в этом множестве- контроллер домена.** 

### Структура доменных имен

* Есть корневой домен - он обозначается как десятичная точка. Он управляется ICANA
* Он разделяется на поддомены - домены первого уровня:
	* Домены организаций (com - коммерческие, org - некоммерческие, edu - обучение, mil - военные). Они все **ТРЕХБУКВЕННЫЕ**
	* Географические домены (us - Штаты, ru - Россия) . Они все **ДВУБУКВЕННЫЕ**
	* Есть еще local - он нужен для создания Intranet
	* in-addr.arpa. - домен обратного просмотра (для просмотра обратной зоны - просмотра имени по ip)
		* Если домен заканчивается `.`, то нельзя после нее ничего дописать (такое дополнение называется суффиксом)
		* Собственно, прямой просмотр - это просмотр IP по имени
	* На этом уровне нет компьютеров, ТОЛЬКО DNS-серверы
	* Полное имя домена пишется как имя устройство.домен.... (и так далее. Главное - не более 256 символов, считая точки)
* Всего есть 13 корневых серверов. Они имеют уровень A.
* Уровень B (поддомен первого уровня) - это, например, DNS-сервер, ответственный за зону .ru

* В любом домене (кроме корневого) могут быть определены имена узлов
* В доменных именах допускаются латиница в любых регистрах, цифры и дефис. Кстати, DNS не чувствителен к регистрам

* Для каждого домена есть DNS-сервер
	* Там может быть описание домена, но зачастую за это отвечают поддомены
	* Если DNS-сервер содержит описание для зоны, то он называется 

### Термины

* DNS-сервер - узел, содержащий информацию о структуре DNS-домена и обрабатывающий DNS-запрос
	* Клиент может иметь до 3 DNS-серверов

* DNS-resolver - программа для работы с адресами
	* Есть два режима работы:
		* Рекурсивный (клиент делает запрос, а сервер говорит, есть ли такой узел или нет)
		* Итерационный - клиент сам будет запрашивать у системы адреса, пока не получит его

* Зона - непрерывное пространство имен (конкретная БД, она соответствует только части домена)
	* Домен - это пространство имен

### Разрешение имен DNS
1. DNS-ресольвер обращается к кешу результатов обработки DNS-запросов, в частности к gethostbyname()
2. Если кеш не содержит ответа, то ресольвер посылает запрос на DNS-сервер
	* Один из параметров настройки узла является IP DNS-сервера, который разрешает имена
	* Если таких адресов несколько, то он обращается в порядке их упоминания
	* Если же их нет, то эта информация возвращается
3. Дальше уже DNS-сервер идет по трем путям:
	1. Обращается к файлам зон
	2. Обращается уже к своему  кешу результатов обработки DNS-запросов
	3. В крайнем случае, обращается к вышестоящему DNS-серверу

* Forward NS lookup zone

* Есть еще и reverse NS lookup zone. Это зоны обратного просмотра. С помощью них можно определять доменное имя по IP.
* Все адреса мы пишем в обратном порядке (снизу вверх), бтв

### Ресурсные записи
* Зонные файлы состоят из записей.
* Такая запись состоит из [Owner] [TTL] [Class] Type Data
	* Owner - владелец, если не указано, то подтягивается из вышеидущего
	* TTL - Time To Live
	* Class - используемый стек протоколов (IN для интернета)
	* Type - тип
	* Data - значение

* SOA - запись в начале файла, содержит следующую инфу:
	* Owner, TTL, Class, Type
	* Authoritative Server - основной сервер зоны
	* Responsible person - почтовый адрес администратора, ответственного за зону
	* Serial number - порядковый номер ВЕРСИИ зоны.
		* Если версия соответствует исходному, то все ок.
		* Иначе - получаешь актуальную версию.
		* Если вдруг у вас только один DNS-сервер, то с ним можно не запариваться (хотя это редкость).
	* Refresh - интервал в секундах, с которым проверяются наличия изменений
	* Retry - интервал в секундах, через который дополнительный сервер повторит попытку запроса
	* Expire - интервал, через сколько после разрыва данные на сервере будут считаться невалидными
	* Minimum TTL - TTL по умолчанию

* NS - авторизованный DNS-север
	* A - сопоставляется доменному имени IP по ipv4
	* AAAA - сопоставляется доменному имени IP по ipv6
	* PTR - для зоны обратных просмотров

* MX - определяет имя почтового сервера
* SRV - указываются типы сервисов в домене.
