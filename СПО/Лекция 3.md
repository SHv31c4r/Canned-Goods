## Как строить распознаватель

* Для регулярных языков распознаватели - это односторонние автоматы без внешней памяти (они же конечные автоматы).
* КА задается пятеркой:
	* Q - конечное множество состояний
	* V - алфавит автомата
	* `delta` - функция перехода
	* q0 - начальное состояние
	* F - Множество конечных состояний
* Он принимает цепочку, если при ее получении он может пройти из начального состояния в любое финальное.
* КА называется детерминированным, если из одного состояния есть не более одного перехода в другое по данному символу.
	* Это условие касается всех состояний
* Иначе автомат недетерминированный
	* Такой автомат - это жопаболь для программиста
	* Надо обрабатывать каждый из путей, что очень затратно по ресурсам

* Свойства КА:
	* Для любого конечного автомата можно построить его детерминированный эквивалент.
	* Автомат можно минимизировать. В худшем случае, он останется таким же.

* Как строить КА для регулярной грамматики:
	1. На основе регулярной грамматики строится эквивалент в лице автоматной грамматики
		* Отличие автоматной грамматики от регулярной: в зависимости от стороны грамматики в автоматной грамматике всегда стоит только ОДИН терминальный символ
		* Так что автоматная грамматика - это частный случай регулярной грамматики.
		* Делается это разбиением регулярной грамматики так, чтобы она стала автоматной
			1. Устраняются все цепные правила (все правила вида A->B)
			2. Устраняются правила с пустыми переходами
			3. Переносятся все нетерминальные символы
			4. Ну и теперь уже дробим правила по необходимости
	2. На основе этой грамматики строится конечный автомат
		* Просто делаем эквиваленты, как на теории автоматов

Можно распознавать лексему на то, что это спец слово как на этапе чтения лексемы, так и после ее прочтения.

**тут нам объясняли пример**

* проблема - конструкции, которые порождаются при построении автоматов, очень громоздкие
* Решение - использовать регулярные множества
	* Регулярные множества - множества цепочек символов, построенных с использованием операций объединения, конкатенации и операции Клини (она же итерация).
	* Регулярные выражения - это способ обозначения регулярных множеств

**КОРОЧЕ, тут все идет из курса ТА**

* Есть проги, которые строят на основе РВ строят шаблон программы распознаватель на ЯП (пример - LEX) (Если есть возможность, то можно такими программами пользоваться)
* Но преобразователь (который нам и требуется) нужно уже самому дописывать.

* Свойства регулярных языков
	1. Задаются разными способами: с помощью регулярной грамматики, КА, РВ итд. Все способы эквивалентны
	2. Один способ можно спокойно перевести в другой (это про проблему эквивалентности)
	3. Любую регулярную грамматику можно привести к однозначному виду. (это про проблему однозначности)
	4. Регулярные языки замкнуты относительно множества следующих операций:
		1. Итерация
		2. Конкатенация
		3. Объединение
		4. Дополнение
		5. Пересечение
		6. Гомоморфизм (если в одном языке заменить символ/цеопчку на что-то из другого, то все будет ок)

# Синтаксический анализ и контекстно-свободные (КС) языки

* Синтаксический анализатор - часть компилятора, что отвечает за синтаксический анализ конструкций входного языка.
	* Если без лексического можно обойтись (просто скинув всю работу на синтаксический), то этот уже обязательный
	* Что он должен делать:
		* Находить и выделять синтаксические конструкции в тексте исходной программа
		* Устанавливать тип и проверять правильность конструкции

* Синтаксис ЯП описывается при помощи КС-грамматик, но **ЯП != КС-язык**
* Как строить синтаксический анализатор
	1. Построить распознаватель на основе грамматики
	2. Выбрать форму для внутреннего представления программы и организовать запись результатов в выбранной форме

* Распознаватель для КС-языков - это автомат с магазинной памятью (МП-автомат) (со стеком)
	* Q - множество состояний
	* V - входной алфавит
	* Z - специальный конечный алфавит магазинных символов
	* `delta` - множество правил
	* q - начальное состояние
	* z - начальный символ магазинного алфавита
	* F - множество финальных состояний
* Он может совершать lambda-переходы: не считывает входной символ, но работает с магазинной памятью
* Такой автомат допускает цепочку, если он может перейти из начального состояния (в стеке должен быть хотя бы один символ из магазинного алфавита) в финальное состояние так, чтобы стек был пуст, а входная цепочка будет полностью прочитана.
* Автомат может быть детерминированным, если для каждого состояния при любом входном символе и любом символе в стеке есть не более одного перехода.
	* Проблема - не для любого недетерминированного МП-автомата можно построить детерминированный эквивалент
Детерминированный МП-автомат определяет детерминированный КС-язык (ДКС-языки)

* Есть расширенная версия, которая считывает целую цепочку
