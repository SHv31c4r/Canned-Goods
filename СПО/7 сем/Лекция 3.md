# Про системы программирования

* Системы программирования - комплекс программных средств, решающих задачи создания и поддержки программного обеспечения на этапах его разработки Ю отладки, тестирования и сопровождения.
	* Они же IDE, среда разработки
	* Она обеспечивает поддержку всех этапов жизненного цикла продукта, КРОМЕ проектирования. Хотя некоторые IDE на это могут быть ориентированы.
	* Для проектирования используют CASE - Computer Aided Software Engineering
	* Компилятор в них включен. Хотя они могут включать несколько компиляторов

* Какие программные модули в них имеются:
	* Текстовые редакторы
	* Компиляторы
	* Компоновщики ()
	* Библиотеки
	* Загрзучики
	* Отладчики
	* И другие (редакторы UI)

* Как она работает
	1. Исходный код подается в компилятор
	2. Полученная объектаня программа попадает в компоновщик, где подключаются библиотеки. Получается исполняемый файл
	3. Исполняемый файл попадает в загрузчик или отладчик. Загрузчик занимается работой с адресами (например, я чут-чут не поймал)
		* Еще в загрузчик попадает пользовательский интерфейс. Для него используется свой компилятор, который ресурсы UI  передает в компоновщик и загрузчик
		* UI можно писать текстом, можно в в графике, зависит от IDE

* Развитие
	* В начале все существовало раздельно, были только текстовые редакторы
		* Исходный код по команде подавался компилятору, порождалась объектная программа
		* По команде компоновщику подавались все полученные объектные программы. Получалась объектная программа.
		* И чтобы она выполнялась, нужно было также подавать команду
	* Первый шаг - объединили компилятор, компоновщик и библиотеки (где-то в 60-70-х).
		* Тут появился инструмент - язык описания, из каких компонентов состоит проект, какие библиотеки используются.
		* Описание составлялось один раз
		* Была утилита-интерпретатор, который выполнял все действия на основе описания
			* Утилита называлась MAKE. Обрабатываемый файл назывался makefile (привет, UNIX и Linux)
		* В результате эволюции ОС загрузчик перешел в нее. Так что теперь это стало именно ее работой
	* Интегрированные среды
		* К инструментам добавился текстовый редактор.
		* В нем уже можно было выполнять все действия с тем инструментом, выполнять команды итд
		* Они позиционировалсь как инструменты для начинающих/обучающихся
		* Но в процессе оказалось, что она удобная еще и для проффесиональных программистов. Так что началось противостояние проффесиональных и интегрированных сред
			* Нельзя сказать, что более ранние инструменты исчезли, они все еще используются. Тот же самый MAKE используется для сборки 
	* Некст этап - появление графических систем
		* Появилась графическая среда разработка и редакторы с визуальной настройкой UI

* Функции текстового редактора
	* Основная - создание и модификация кода исходной программы
	* Преимущества
		* Анализ кода на лету - пишешь код, а он уже подсвечивает тебе некоторые ошибки. Сюда еще относится подсветка синтаксиса. Тут выполняется лексический и часть синтаксического анализа
		* Контекстные подсказки - показывает, какие поля есть у метода/класса/структуры. Так что тут отсекаются некоторые ошибки.
		* Отображение информации об ошибках и предупреждения в самом исходном коде программы. IDE сама компилирует имеющийся код и порождает сообщения об ошибках
		* Отладка результирующей программы по коду исходной программы. А вот тут уже несколько интереснее, так как тут мы ставим какие-то метки по исходному коду, а выполняется у нас исполняемый файл с отладчика. Исходная программа не выполняется
			* Компилятор добавляет в объектную программу отладочную информацию. А вот компоновщик уже собирает исходную программу с ней всей. И уже в исполняемом файле все эти пометки появляются
			* Отладчик работает с исходной программой устанавливает соответствия по адресам, где какая строка исходной программы
			* Современный отладчик включает в себя обработчик прерываний, чтобы те же самые точки останова работали. По коду встретили прерывание - начинаем обработку прерывания со всей отладочной информацией

* Функция компилятора (он должен быть)
	* Некоторые IDE позволяют работать с несколькими языками
	* В общем случае для каждой комбинации "входной язык - целевая система" нужен свой компилятор. Так что, как правило, теперь компиляторов несколько в одной IDE
	* Ну и для графики свой компилятор должен быть
		* Графику текстом писать - тихий ужас. Так что должен быть и интерпретатор для графики.
		* Сам make тоже интерпретатор, так что и он тоже должен быть включен в IDE
	* Компилятор дополнительно должен выполнять еще такие функции:
		* Взаимодействовать с текстовым редактором
		* Уметь работать с отладочной информацией и формировать ее так, чтобы она была применима на дальнейших этапах

* Компановщик (редактор связей/линКовщик) - связыввет несколько объектных файлов и библиотек в один исполняемый файл
	* Если он какую-то связь не смог обрабатывать, то он породит ошибку об этом
		* Сначала он ищет в локальных файлах, потом в подключенных к проекту библиотеках. Забыл указать - ебать ты лох, он пожалуется
		* Указал неправильное 
	* Как и компилятор, он работает с относительными адресами
	* В некоторых языках есть ключевое слово external для функции, вызываемой извне.
		* Зачастую, компилятор еще добавляет различные символы, чтобы гарантировать уникальность имени и отсутствие конфликтов
		* Забыл указать как внешнюю - он добавит свои символы, а компоновщик ее не сможет найти. Имя-то другое.
		* Но тогда ты сам уже должен гарантировать уникальность имени
